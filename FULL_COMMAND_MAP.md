# Полная карта команд Siemens NX 2512

В репозиторий добавлен компилятор, который превращает иерархический каталог из **1169 команд** в безопасный профиль NXKeys с последовательностями вызова.

## Что изменено

- Все команды из исходного каталога сохранены в 32 разделах единого версионируемого снимка в `config/full-command-map/`. Снимок разбит на три компактные части `json.gz.b64.part1–part3`, а компилятор объединяет и проверяет их автоматически.
- Для каждой команды зафиксированы:
  - исходный раздел и группа;
  - коэффициент частоты `K1–K5`;
  - английское и русское название без изменения исходных разделителей и составных обозначений (`DXF/DWG`, `Zoom In/Out` и подобных);
  - целевой адаптивный модуль NXKeys;
  - мнемонический путь `действие → объект → команда` длиной 2–5 клавиш.
- Пути проверяются на уникальность и конфликт префиксов.
- Существующие проверенные `BUTTON ID` и ручные сочетания имеют приоритет.
- Неизвестные команды не получают выдуманный `BUTTON ID`: компилятор ищет точное соответствие в каталоге конкретной установки Siemens NX.
- Команды, отсутствующие из-за лицензии, роли или состава установки, остаются в профиле с назначенным путём, но отключаются и попадают в отчёт.

## Быстрый запуск

Сначала сформируйте каталог через `NX2512_Catalog_Studio`. В папке результата должен находиться файл:

```text
06_ui_commands_buttons.csv
```

Затем выполните:

```powershell
.\install-full-command-profile.ps1 `
  -CatalogDir "D:\NX2512_Catalog_Output" `
  -NxRoot "C:\Program Files\Siemens\NX2512" `
  -Clean
```

Только собрать профиль без установки:

```powershell
.\install-full-command-profile.ps1 `
  -CatalogDir "D:\NX2512_Catalog_Output" `
  -CompileOnly
```

Результаты:

```text
config/nx2512-pro-full.generated.json
docs/generated/full-command-resolution.md
```

## Ручная компиляция

```powershell
node .\scripts\compile-full-command-map.mjs `
  --profile .\config\nx2512-pro-hybrid.json `
  --intents .\config\full-command-map `
  --catalog-dir "D:\NX2512_Catalog_Output" `
  --out .\config\nx2512-pro-full.generated.json `
  --report .\docs\generated\full-command-resolution.md
```

Глобальные команды по умолчанию добавляются во все активные модули, чтобы файловые операции, просмотр, измерения, Teamcenter и администрирование были доступны без ручного переключения HUD. Для отключения дублирования используйте `--no-global-duplication`.

## Политика путей

Канонический путь строится по модели:

```text
CapsLock → действие → объект → команда
```

Примеры корневых действий:

```text
C Create      E Edit        T Transform   X Remove
P Process     I Inspect     V View        S Select
A Annotate    M Manage      F File        U Utilities
```

Компилятор выполняет следующие правила:

1. Сохраняет существующие проверенные пути для известных `BUTTON ID`.
2. Выделяет отдельные пространства объектов: Feature, Body, Surface, Operation, Tool, Routing, Simulation и другие.
3. Устраняет одинаковые пути и ситуации, когда одна команда является префиксом другой.
4. Сохраняет короткий alias только тогда, когда он не затеняет команду или подменю.
5. Отключает неоднозначно разрешённые команды вместо рискованного автоматического выбора.

## Проверка

```powershell
node .\scripts\validate-full-command-map.mjs
```

Проверка подтверждает:

- ровно 1169 исходных команд;
- наличие всех 32 разделов;
- корректность `K1–K5`;
- уникальность идентификаторов источника;
- отсутствие конфликтов путей;
- сохранение каждой исходной команды в сгенерированном профиле;
- отсутствие включённых команд без точного `BUTTON ID`.

## Почему профиль компилируется на компьютере с NX

Иерархический список задаёт функции, частоту и удобный путь, но не содержит гарантированных `BUTTON ID`. Эти идентификаторы зависят от состава установленной NX, лицензий, роли и корпоративных расширений. Поэтому карта разделена на два слоя:

1. **Полный слой намерений:** все 1169 команд всегда присутствуют и имеют путь.
2. **Исполняемый слой:** точные `BUTTON ID` разрешаются из `06_ui_commands_buttons.csv`; найденные команды включаются, неоднозначные и отсутствующие безопасно отключаются.

Это исключает ложные идентификаторы и позволяет одному репозиторию работать с разными комплектациями Siemens NX 2512.
