# Быстрый Selection Intent в NXKeys

NXKeys v8 добавляет отдельный in-process механизм выбора геометрии для активных NX collectors. Он предназначен для ситуаций вроде Extrude, Sweep, выборов кривых/рёбер/граней и других команд, где способ распространения выбора важнее самого фильтра типа объекта.

> Это **не то же самое**, что универсальные Leader-фильтры `S → B`, `S → F`, `S → E` и т. п. Leader-фильтр отвечает на вопрос «какой тип объекта выбирать», а Selection Intent `0…4` — «как распространить выбор от выбранного объекта».

## Клавиши

| Клавиша под `CapsLock` | Прямой ввод | Режим | Практический смысл |
|---|---|---|---|
| `CapsLock → ~` | `0` | Reset | вернуть обычное поведение NX и отключить intent toggles |
| `CapsLock → Q` | `1` | Single | один объект без автоматического расширения цепочки |
| `CapsLock → W` | `2` | Connected / Chain | связанные кривые/рёбра как цепочка |
| `CapsLock → E` | `3` | Tangent | касательно связанные кривые, рёбра или грани |
| `CapsLock → R` | `4` | Inferred Path / Region Boundary | inferred path, boundary/region-подобный выбор |

Рекомендуется использовать эргономичный леворучный аккорд `CapsLock → Q / W / E / R / ~`, также поддерживается прямой ввод `1…4 / 0` при активном collector.

## Когда клавиши перехватываются

Handler не должен превращать клавиши в глобальные hotkeys. Событие обрабатывается только если одновременно выполняются условия:

- foreground window принадлежит текущему процессу NX;
- не зажаты Ctrl, Alt или Win;
- фокус не находится в текстовом поле/редакторе;
- событие не является injected keyboard event;
- доступен один из native selection-intent controls NX **или** уже существует выбранный seed-объект.

Если этих условий нет, клавиши передаются NX/Windows как обычный ввод.

Физическое удержание клавиши защёлкивается до `key-up`, поэтому keyboard autorepeat не должен многократно переключать режим.

## Native NX controls

Runtime использует доступные элементы NX 2512:

```text
UG_SEL_CHAINING
UG_SC_INFERRED_CURVE_SELECTION
UG_SC_CHAIN_WITHIN_FEATURE
UG_SC_BOUNDARY_EDGES
UI_CURVE_FINDER_TANGENT
UI_FACE_FINDER_TANGENT
```

Для seed-based expansion дополнительно используются совместимые методы `ScRuleFactory` через reflection. Такой подход позволяет собирать Bridge в CI против минимальных contract stubs, а в реальной NX использовать более богатый API.

## Что делает каждый режим

### `0` / `CapsLock → ~` — Reset

Отключает chaining, inferred path, boundary и tangent toggles. Используйте, если после сложного выбора нужно вернуться к стандартному поведению NX.

### `1` / `CapsLock → Q` — Single

Отключает intent toggles. Если до переключения было выделено несколько объектов, runtime старается оставить последний выбранный seed.

### `2` / `CapsLock → W` — Connected / Chain

Включает native chaining, отключает несовместимые tangent/path toggles. Если seed уже выбран, runtime дополнительно пытается расширить выбор NXOpen rule для цепочки.

### `3` / `CapsLock → E` — Tangent

Включает native curve/face tangent selectors и отключает chaining/path/boundary. Благодаря native toggles режим можно выбрать **до первого клика**. Если seed уже существует, применяется дополнительная rule-based expansion.

### `4` / `CapsLock → R` — Inferred Path / Region Boundary

Включает chaining + inferred path + boundary controls. При наличии seed runtime пытается построить boundary/feature rule, подходящий типу выбранного объекта.

## Типовые сценарии

### Extrude по одной кривой

```text
1. Откройте Extrude.
2. Перейдите в collector Section/Curve.
3. Нажмите CapsLock → Q (или 1).
4. Выберите нужную кривую.
```

### Extrude по связанной цепочке

```text
1. Откройте Extrude.
2. Когда активен collector, нажмите CapsLock → W (или 2).
3. Выберите одну кривую цепочки.
4. Проверьте подсветку всей ожидаемой цепи.
```

### Касательная цепочка

```text
1. Активируйте collector.
2. Нажмите CapsLock → E (или 3).
3. Выберите стартовую кривую/ребро/грань.
4. Убедитесь, что NX расширил выбор только по касательности.
```

### Граница области

```text
1. Активируйте подходящий collector.
2. Нажмите CapsLock → R (или 4).
3. Выберите seed или boundary element.
4. Проверьте, что NX выбрал ожидаемую границу/путь.
```

### Сброс

```text
Нажмите CapsLock → ~ (или 0), затем продолжайте обычный выбор NX.
```

## Чем это отличается от `S → …`

Пример совместного использования:

```text
CapsLock → S → E    приоритет рёбер (тип)
CapsLock → E        распространение выбора по касательным рёбрам (intent)
```

Первый механизм задаёт **тип**, второй — **intent/правило распространения**.

## Ограничения

- доступность native toggles зависит от конкретного NX collector;
- rule expansion зависит от типа seed и возможностей `ScRuleFactory` в установленной NX;
- режим `4` не означает один универсальный алгоритм «замкнутая область» для всех commands — используются доступные NX boundary/path semantics;
- contract build CI не доказывает фактическую интерактивную реакцию collector;
- при неожиданном числовом вводе первым делом проверьте, не оставлен ли активным NX collector.

## Диагностика

Если `0…4` ничего не делают:

1. убедитесь, что foreground действительно Siemens NX;
2. активируйте command collector, а не обычное графическое окно;
3. проверьте, что Bridge DLL текущей версии загружена;
4. после обновления **полностью перезапустите NX**;
5. попробуйте сначала выбрать один seed, затем нажать `2`, `3` или `4`;
6. проверьте Bridge/runtime logs;
7. сравните доступность native controls на вашей сборке NX 2512.

Если цифры перехватываются там, где должны вводиться значения, сохраните сведения о focused control, активной NX command и версии Bridge — это считается дефектом guard-логики.
