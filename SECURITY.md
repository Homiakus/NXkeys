# Политика безопасности NXKeys

## Поддерживаемая область

Проект разрабатывается для Siemens NX / Designcenter NX 2512, Windows x64, .NET 8 и file-based local IPC.

Уязвимостью считаются, в частности:

- выполнение другой команды вместо выбранной;
- обход confirmation для destructive operation;
- повторное выполнение запроса после неопределённого результата;
- command injection через config, path, launcher или MenuScript generation;
- запись или удаление файлов вне managed package boundaries;
- небезопасная обработка `UGII_CUSTOM_DIRECTORY_FILE`;
- подмена profile, manifest, Bridge request или result;
- раскрытие локальных путей, данных детали или корпоративной конфигурации;
- загрузка неподходящей или неподписанной Bridge DLL, если это нарушает применимую политику.

## Как сообщить

Не публикуйте эксплуатационные детали уязвимости в открытом issue до согласования исправления.

Используйте GitHub private vulnerability reporting, если эта функция включена для репозитория. Если она недоступна, свяжитесь с владельцем репозитория через его подтверждённый GitHub-профиль и передайте минимальную информацию, необходимую для установления безопасного канала.

Не отправляйте:

- license files Siemens;
- proprietary NXOpen binaries;
- детали, чертежи и производственные данные;
- токены, пароли и внутренние адреса;
- полные корпоративные `.mtx`, `custom_dirs.dat` или logs без очистки.

## Что включить в отчёт

- затронутый commit или release;
- версия Windows и NX;
- компонент: HotkeyStudio, Bridge, Control Center, Catalog Studio, installer или compiler;
- безопасные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- оценка возможного воздействия;
- обезличенные logs и request/result JSON;
- наличие destructive command или производственных данных в сценарии.

## Безопасное воспроизведение

- используйте копию тестовой детали;
- не проверяйте destructive-команды на production data;
- не изменяйте системные файлы Siemens;
- не отключайте backup/manifest проверки ради воспроизведения;
- удаляйте из артефактов абсолютные пути и идентификаторы организации;
- при подозрении на повторное выполнение сохраните `pending`, `processing`, `completed`, `failed`, `context.json` и `status.json`, не перезапуская команду.

## Границы проекта

NXKeys снижает риск ошибочного dispatch, но не является sandbox, системой авторизации Siemens или средством резервного копирования производственных данных. Фактическая безопасность зависит также от NX, лицензий, роли, ОС и политики организации.

Contract tests против NXOpen stubs не доказывают безопасность runtime integration. Исправления Bridge должны проверяться в целевой лицензированной NX.

## Секреты и чувствительные данные

В version control запрещено добавлять:

- API keys и access tokens;
- пароли и credentials;
- закрытые license materials;
- proprietary Siemens binaries;
- персональные данные;
- реальные производственные файлы;
- внутренние network paths, если они раскрывают инфраструктуру.

Используйте placeholder paths и синтетические examples.
